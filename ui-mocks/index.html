Sync tab UI proposals

Mock-ups only. Nothing here is wired to a backend, and no plugin code has been changed.

The comment these answer
"The UI change is making me think there is further UI improvements around consistency and clutter. Top on my list are the cache count down, as it moves position on different tabs. I think it should be consistently left of the refresh button. Then there is the interface tab sync option check boxes. They take a lot of space and add visual clutter. I think we could consolidate the exclude options and the auto select lag into either a expandable toggle or maybe modal to the right of the sync buttons."

Worth knowing before this is built The countdown currently lives inside the content fragment, which is the element HTMX replaces on refresh. The header row is outside that target, so moving the countdown there means a refresh no longer repaints it. It needs either an out-of-band swap or the header moved inside the swap target. Also, the five tabs use five element ids (countdown-timer, cable-countdown-timer, ip-countdown-timer, vlan-countdown-timer, module-countdown-timer) and five window.*CountdownInterval globals, all initialised from one generic helper. A shared include collapses that to one id and one timer.

Reuses the collapse pattern the tab already uses for filters, so there is no new interaction to learn. It still pushes the table down while open, which is the thing the other two avoid.

Trade-offs, briefly A keeps everything on one screen and needs no new template file; the panel is cramped on a narrow window. B has room to explain each option, at the cost of a dialog in front of a routine action. C matches an existing pattern on the same tab, but reintroduces the vertical shift when open. All three keep the same field names, so the POST payload does not change. The badge count is the part that matters for either choice: without it, a non-default exclude becomes invisible, which is worse than today's clutter.
